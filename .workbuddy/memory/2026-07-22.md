## 用户技术路线决策（重要）
- 用户明确：几何搭建要保住 assembly 可编辑性（primitive 生成的是 assembly，部件可单独编辑），AI 3D 生成模型（单 mesh 不可编辑）不是主路线。
- 用户倾向：LLM 理解物品生成逻辑 → 现场写 generator 代码 → 执行生成 parts[] → 每个 part 落独立节点。认为比 primitive 工具更灵活、上限更高。
- 共识设计：assembly 结构不变，part 几何来路从"17 种原子拼装"扩成"代码生成的 BufferGeometry"；role 语义照传，质量门继续可用；generator 脚本+参数存 assembly metadata，revise 时 LLM 改代码重跑（Zoo KCL 模式）。
- 待补工程：① 沙箱（Worker/isolated-vm，白名单几何 API，不能复用 asset-component-generator-runner 的 execFileSync 直跑）；② 新增 GeneratedMeshNode 存几何+脚本+参数；③ revise_geometry 升级为改代码重跑、按 part id diff 保留未变部件状态；④ 报错回喂 LLM 修复 2-3 轮。
- 演进方向：好 generator 可沉淀回 workspace 复用调参（复利）；part 未来可按 id 替换成 AI 3D 精模（演进非替代）；工业件继续走 recipe/profile 不动。

## 技术路线最终共识（与另一份分析对比后）
- 另一份分析更深入：根因不止 primitive 弱，而是归一化器静默丢字段（degrees→[0,0,0]、subArray 不识别、back_top 降级），证据在 ai-geometry-tool-normalizers.ts / ai-geometry-tool-relations.ts:343 / primitive-compose.ts:389。
- 最终路线（以对方为准）：① 先修编译器（不静默吞、报错回喂 LLM，本周可做收益最快）；② Typed Assembly IR（world/local transform、hinge、grid、partId 引用显式建模，IR 是真相来源，mesh 是渲染产物）；③ 受限 DSL（通用计算+白名单几何 API）+ 进程/容器级隔离（vm/Worker 不算安全边界）；④ GeneratedMeshNode 存可序列化 mesh + IR + 版本哈希，手工改动存 partId override 层。
- 我保留的一条约束：DSL 必须是"图灵完备表达 + 收窄几何 API"，不能退化成只有 part()/grid() 的声明式 schema（否则就是又一个 primitive 工具）。grid() 是糖，for 循环是底。
- 勿复用 ItemNode（其契约是外部 GLB URL）和 asset-component-generator-runner 的 execFileSync（只适合可信 pack）。

## 数据模型最终形态（两处校正，已确认正确）
- 三层真相模型：DSL source+params（作者真相，用户意图改动入口）→ Assembly IR（场景真相，可审计可 diff，每次成功生成后重算）→ mesh（渲染产物）。同一份 DSL 可因代码修改/API 升级/随机种子产出不同 IR，所以必须拆开。
- 修订循环：用户说"键帽大一点"→ 改 DSL 参数 → 重跑出新 IR → 按稳定 partId 把 override 重新叠加。diff 的是 IR 层 partId 集合，不是 mesh。
- 存储：Assembly 根集中持有 DSL/params/IR/版本哈希/生成记录（唯一修订入口）；每个 GeneratedMeshNode 只存 partId/mesh 引用/局部 transform/材质/语义/override。避免 N 份冗余，override 可重放。
- 待落地细节：partId 必须确定性生成（key_${row}_${col} 而非随机），IR 校验检查重跑前后 partId 连续性，消失的 id 的 override 标记"孤儿"而非静默丢弃。

## Docker 天空颜色差异修复（2026-07-22 下午）
- 问题：Docker 部署的天空是蓝色渐变（backgroundSky 生效），本地是灰白色（backgroundSky 未生效，退化为平色 background）。用户希望 Docker 同本地。
- 根因：`.dockerignore` 没排除 `packages/*/dist`，`COPY . .` 带入宿主机旧 dist；Dockerfile 只跑 `next build`，不重新编译 viewer/nodes 等包的 dist。Next.js 的 `transpilePackages` 入口仍是各包 `dist/index.js`。
- 修复：Dockerfile builder 阶段在 `next build` 前增加 `bun --cwd=packages/{core,viewer,nodes,mcp,articraft-bridge} run build`（tsc --build），确保 dist 最新。构建顺序按依赖：core → viewer → nodes。
- 注意：packages/editor、plugin-* 无 build 脚本，不在列表中。
