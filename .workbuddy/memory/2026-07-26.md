1. **dist 未构建**：500 `Can't resolve '@pascal-app/core/schema/nodes/generated-mesh'`——core 新 schema 没 `bun run build`。修复后构建又报 TS2307：`generated-mesh.test.ts` 包名自引用（core 内部必须相对路径）。
2. **exports 不覆盖深层子路径**：build 过后 500 依旧。真根因：`@pascal-app/core` exports 只有精确键 + `./lib/*` 通配，`./schema/types`、`./schema/nodes/xxx` 匹配不到任何键。4 个文件改从 `@pascal-app/core/schema` 桶文件导入。
3. **sandbox worker crash**：HTTP 冒烟路由成功（laptopLike 信号命中 needs_hierarchy/hinge/grid/computed_layout），但 `dslDowngrade.reason=sandbox_error`，worker exit code=1。根因：`fork()` 启 `.ts` worker，dev server 是 Node 宿主跑不了 TS；且 `stdio` 全 ignore 吞了 stderr。**单测全绿是因为注入 mock forkImpl 从没真起子进程**。修复：fork 加 `execPath: process.execPath`（bun 宿主→bun worker）+ stderr 改 pipe 捕获前 4KB，crash message 带 stderr 前 500 字符。

**二次修复（execPath 方向错了）**：stderr 捕获立刻见效，报 `Unknown file extension ".ts"`——**`bun --cwd apps/editor dev` 只是用 bun 当包管理器拉起 `next dev`，Next 自己 fork 的 server 进程是纯 Node，`process.execPath` 指向 node.exe**。改为 `resolveBunExecPath()`：优先 `DSL_SANDBOX_EXEC` env 覆盖 → `where bun`（Win）/`which bun` 探测 PATH → 兜底 `process.execPath`。

**三次修复（幽灵 shim）**：`where bun` 在 Node 子进程的 cmd 里找到 `D:\Program Files\nodejs\npm_global\bun`——npm 全局目录下的**失效 shim**（bun 已卸载/移动），spawn ENOENT。用户 PowerShell 里 `where bun` 为空（cmd 和 PS 搜索路径不同）。修复：`resolveBunExecPath` 收集所有候选（env 覆盖 / PATH 命中 / Windows+Unix 常见安装目录如 `%USERPROFILE%\.bun\bin\bun.exe`）后**逐一 `existsSync` 验证存在性**，失效 shim 自动跳过。

**四次修复（npm 全局 bun）**：`Get-Command bun` 返回 `D:\Program Files\nodejs\npm_global\bun.ps1`——bun 是 **`npm i -g bun` 装的**，ps1 只是 shim，真实二进制在 `<npm-prefix>\node_modules\bun\bin\bun.exe`。`resolveBunExecPath` 增加 `npm prefix -g` 探测候选。

冒烟脚本同步修复：succeeded + dslDowngrade 单独分支（不再误报 "did NOT go through generator_dsl"）。

**教训**：bun test 的三个盲区——dist 缺失、exports 深层子路径、fork 真实子进程，只有 e2e 能抓。
